another piece of the astra tiktok doomscrolling project. when doing a pilot i realized it could make chibi vtuber models, so i was curious if it could make a decently professional-looking one like the ones vtubers use. the model was designed by astra, but the rigging was done by hand.

i do want to try other programs that allow for more automation in rigging. don't see why it shouldn't work. cmo3 (cubism's project file) is proprietary and undocumented, so building a rig somewhere else and importing it isn't really an option. people have partly reverse engineered it, but nothing official. cubism 5.4's alpha does open an api that can set up the rig's structure (parameters, deformers, parenting), just not the actual shaping, so that's probably the way in.

this made me curious about 3d models as well, but we'll see if i ever get around to that.

01Lessons learned, in no particular order

if i did it again

the art

starting with a concept drawing is good enough. it's ai, yes, but gpt-6 astra is very competent at photoshop. like... super good.

live2d cubism needs every movable part on its own layer. this file ended up with 113 pieces on a 4000×6000px canvas. it's extremely surprising this model can work with files this huge.

when generating the model, make sure it's more or less symmetrical. cubism can mirror, so you don't have to rig everything twice (like me..).

have a rough idea of which parts move before you start. fortunately this model didn't have much (she's female but she's flat LOL). sorting that out up front, before rigging and fiddling with the physics, is very important.

it's also good to know which pieces are cropped badly. if i could start over, i'd have astra redo the hair cropping. it's cropped for convenience in photoshop, not for convenience in cubism.

although astra is very good at photoshop, small edits to pieces sometimes throw the color off or kind of break stuff. i had opus 5.5 do the shading and color correction; for some reason i couldn't get astra to do it competently. probably a skill issue, but heads up if it isn't.

i didn't get into expressions or changeable outfits, but if you use ai for the artwork, consider them up front. i would've added them later, but i kind of got to "eh, this is good enough" and called it.

keeping track of the pieces

to manage all the pieces, i had it make a spreadsheet of every part with a coordinate system for where each one goes, and eventually a tracker for which parts go where. there's a lot of nesting in cubism (body z rotation > body x rotation > breath idle & each piece of the body > head z rotation > etc. etc.). keeping track of what's childed under what, and which layer it's on, is super helpful.

cubism can export the parts and parameters. if you have the original parts list, it's super easy to see which parts you're missing or accidentally deleted or misnamed. creating each parameter and having the llm you're working with remember what goes in it is also very helpful.

rigging

unfortunately, you still have to organize and assign parent deformers and whatnot manually (for some reason every file imported backwards, so i had to arrange everything back to front). you also have to assign the deformers to the parameters, and the parameters individually too. very tedious work, i did not enjoy it. it was rewarding to see that i could mold the face rotation pretty decently though, i'd say.

if you're really bad at illustration and shape rotating like me, it helps to have accurate references of what, for instance, the head looks like at x=30 degrees. i kind of free-balled it, but llms could probably make "dummy poses" you can just warp the rig to match. this is a 2d representation of a 3d object. if you use cubism's built-in rotation tools, it comes out like paper mario. it looked very bad, so i had to bite the bullet and accept that i'd have to do some 3d modeling.

honestly, i don't know what the physics dialogue is for. i asked multiple times and couldn't get it to work or see its purpose. for simple models maybe it isn't necessary. but there's a physics import, and llms can deepfake the physics sheet. idk if it made any difference. who knows.

time & tools

honestly, the model with separate psds and stuff can be cooked in a few hours, probably quicker with an efficient pipeline for this type of work. most of the time (~12 hrs raw?) was in cubism.

the experimental cubism 5.4 supports direct api usage (though i'm not sure how much). it's likely that in the future you can just mcp your llm into it.

if you're putting the model on the web: the player i used (as of writing) only reads models exported as SDK 5.0, so there isn't clean backwards compatibility. live2d's own newer web sdk does read 5.3 exports.
